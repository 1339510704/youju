PART 02

怎么得到一个「解」

三档判定，不硬给结论
可以给结论
多个独立权威来源一致
同一个说法被 ≥2 个不同域名的官方/学术/主流站点独立提到，且没有发现反例——这时给出明确答案，并标清每个独立来源。
只能说存疑
来源单一 或 存在冲突
只有一个来源，或不同来源说法互相矛盾——不给结论，把两方原话并排，让你自己判断。这是最难做对的一档，也是最该老实的一档。
直接说查不到
没有可用的相关证据
召回里没有与问题直接相关的原文时，明确告诉你查不到，并建议换个说法。把"证据不足"当成一种正常输出，而不是失败。
PART 03

我的用户是谁

可信度，与温度
两种人，同一套能力。
一种是对 AI 答案有异议的人——想知道这句话到底可不可信、依据在哪一行，得拿证据说话（写材料、发声明、群里辟谣）。他们用网页端查证。
另一种是想和家人、情侣多聊两句的人——不需求证，但会一起玩一局「这个说法是真的吗」。他们在家庭小程序里答题，题目从真实检索里出，只从官方／学术／主流摘句子，答对得小红花。

查证是冷的，但它可以是暖的入口：没人会主动去查证一条消息，但一家人会一起玩。玩的时候输的一方去看答案为什么对，可信度这件事就被自然接受了。
PART 04

建产品时想清楚的 8 个问题

一对一浓缩版
Q1 · 官方能力

元宝搜索目前有应对 SEO/GEO 的方案吗？

→

有，但不是逐条识别作弊，而是改写规则——靠权威信源白名单与检索层过滤，让可操纵内容进不了候选池。

Q2 · 我的角色

官方是怎么应对的？我自开发用元宝 API 做 Agent，需要考虑解决 SEO/GEO 吗？

→

官方是釜底抽薪建可信检索层；你作为 API 消费者不必做 SEO/GEO，但必须做消费层的证据准入。

Q3 · 要解决什么

我消费元宝做产品，真正要解决的问题、要不要自研算法、大厂怎么做、最好方式、挑战与卖点分别是什么？

→

你解决的是「搜到之后怎么用」：不必自研检索算法，做轻量场景精排 + 检索预算控制，卖点是场景准入规则与反馈飞轮。

Q4 · 大厂弊端

大厂方案有什么弊端或改进空间？行业里做得好的没做到什么？我不想复刻他们。

→

大厂全押检索层、用通用可信度打分、Pipeline 复杂问题答不全；突破点在消费层准入、可审计证据链、把查询变监测。

Q5 · GEO 残留

元宝只是把 GEO 列为低可信源而非排除，我是不是得处理这些答案？给我消费层核心竞争力的东西。

→

是，降权不等于剔除；你的核心竞争力是「场景化证据信任引擎」——硬拦截 + 场景准入规则 + 可审计证据链。

Q6 · 证据链与信源

答案本就多样，直接呈现证据链让用户自选是否更好？元宝通用信源在垂直领域稍差？用户自有信源能加进去吗？

→

判断成立：证据链就是把判断权交还用户；垂直深度确有天花板；自有信源可经 ima 知识库与 Site/Industry 参数接入。

Q7 · 护城河对比

科研行业和深度研究跟我的产品很类似，他们的经验和护城河是什么？我的又是什么？

→

科研靠拥有并深度标引干净语料，你靠在浑浊网络里定义什么算证据——不同水质下的同一个问题，不竞争。

Q8 · 落地

具体怎么做？落地方式是什么？而且网络信息是不断变化的。

→

双层架构：后台持续维护带指纹与信任层级的证据库消化变化，查询时只在有效证据池里做准入、锚定生成、证据链呈现。

产品里实际落地的八件事

前面是想法，这里是做了什么
01多路召回：自建权威域名定向补充，根域与 www. 双形态并行，按 URL 去重合并
02来源准入：按真实域名六档分级，营销号与自媒体不进答案正文
03时效收口：判断查询有无时效意图，过期内容沉底，旧闻不冒充新鲜答案
04交叉验证：不同域名才算独立，同站多篇只算一次
05冲突并排：检测表述矛盾与数字冲突，两方原话摆出来不替你选
06污染识别：同文逐字重复、夸张用语密度、域名集中度三个信号
07锚定摘取：答案每句是原文子串，点结论定位原文高亮
08反向证伪 + 监测：一键搜反对意见；盯梢模式持续追踪变化
CORE TAKEAWAY

不追着网络跑，让架构消化变化——
我的壁垒不是搜得更准，而是更懂在我的场景里，什么才算证据。
